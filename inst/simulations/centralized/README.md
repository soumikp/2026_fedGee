# Centralized simulation (manuscript Section 6)

Produces Tables 1–2 of the main text and Web Tables S3–S4 of the supplement.

## Design

Binary outcomes from a marginal logistic model, generated by thresholding a latent
Gaussian variable with patient-level correlation 0.30 and site-level correlation 0.05.
Visit-level covariate $x \sim N(0,1)$ with slope 1; two to six visits per patient.

| Factor | Levels |
|---|---|
| Number of sites $K$ | 10, 18, 30, 50 |
| Model dimension $p$ | 2, 5, 10, 20 (only $K-p \ge 5$ kept; 13 combinations of $K$ and $p$) |
| Intercept $\beta_0$ | −3, −1, 0 (average prevalence 0.07, 0.30, 0.50) |
| Site sizes | uniform 10–30 patients (CV 0.30); gamma with CV 0.78 or 1.00 (mean 20, minimum 5) |

117 scenarios × 1,000 replicates = 117,000 tasks. All completed.

Each replicate fits federated GEE (working independence) and computes the uncorrected,
KC, MD, and FG variances with normal, $t_{K-1}$, $t_{K-p}$, and Bell–McCaffrey reference
distributions (FG also with its own degrees of freedom), plus pooled GEE and
meta-analytic GEE.

## Files

| File | Purpose |
|---|---|
| `code/01_fedgee_v3.R` | Estimator: federated GEE, score-space KC/MD/FG, Bell–McCaffrey df (function `fedgee_v2`, kept name) |
| `code/00_simulation_config_v3.R` | Data generation, comparators, one replicate (`run_one_rep`), design grid (`build_grid_EV3`) |
| `code/02_run_cluster_v3.R` | Driver: `count`, SLURM array mode, or `local N`; per-replicate time limit |
| `code/collect_results.R` | Combines the 498 array outputs, runs sanity checks, writes `RUN_PROVENANCE.txt` |
| `code/summarize_v3.R` | Quick console summary of the combined output |
| `code/make_statmed_tables_v2.R` | Manuscript tables (per scenario, no averaging) |
| `submit_v3.slurm`, `check_progress.sh` | SLURM submission and progress check (University of Pittsburgh CRC, SMP cluster) |
| `results/statmed_scenario_table.rds` | Per-scenario summary: coverage, SE/SD, bias, df for every method (117 rows) |
| `results/RUN_PROVENANCE.txt` | Code checksums, R and package versions of the run |
| `results/summary_v3.txt` | Console summary of the full run |
| `output/` | Raw output (not tracked; 113 MB) |

## Rebuild the tables

```bash
cd inst/simulations/centralized
Rscript code/make_statmed_tables_v2.R > results/main_table_rows.txt
```

If `output/fedgee_v3_all.rds` exists, the summary is recomputed from it. Otherwise the
tracked `results/statmed_scenario_table.rds` is used. Both paths give identical tables.

## Rerun the simulation

On a SLURM cluster, edit `PROJECT_ROOT` in `submit_v3.slurm`, copy `code/` there, and:

```bash
module load gcc r
Rscript -e 'install.packages("saws")'     # once
FEDGEE_SIM_DIR=$(pwd)/code FEDGEE_EXPS=EV3 FEDGEE_N_REPS=1000 Rscript code/02_run_cluster_v3.R count
sbatch submit_v3.slurm                    # array 1-499, about one hour in total
FEDGEE_PROJECT_ROOT=$(pwd) Rscript code/collect_results.R
```

`collect_results.R` writes `output/fedgee_v3_all.rds`. Then rebuild the tables as above.
Each replicate sets `set.seed(scenario_id * 10000 + rep_id)`, so reruns reproduce the output.
Each replicate runs in a forked child process with a 120-second limit
(`FEDGEE_REP_TIMEOUT`). A time-out is recorded as a failed replicate; none occurred.
